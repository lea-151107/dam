必須の要件

1. pure Go で、cgo・外部コマンド・ネットワークを使わないこと
gvmd を単一のバイナリとして配布するための前提です。

2. 入力と出力
- 入力: Mermaid のソース文字列
- 出力: image.Image（RGBA）
- 端末への出力は gvmd 側の sixel / kitty / iTerm2 エンコーダが担当するので、ライブラリは画像を返すだけで済みます。

3. 描画オプションを外から渡せること

4. エラーの種類を区別できること
- 未対応の図（ErrUnsupported）と、構文エラー（行番号付き）を分ける
- gvmd はどちらの場合もコードブロック表示に戻しますが、構文エラーのときだけ警告を出す、といった使い分けができます

5. 出力が決定的であること
同じ入力からは同じ画像が出ることと、ライブラリのバージョン文字列を公開することです。gvmd はキャッシュのキーに「入力の sha256 + ライブラリのバージョン」を使います。

6. 異常な入力への備え
ノード数の上限や context.Context によるタイムアウトです。巨大なグラフで gvmd 全体が固まるのを防ぎます。

あると嬉しいもの

- 罫線文字での出力（[]string を行ごとに返し、最大幅は桁数で指定）。halfblock / none の端末向けの代わりの表示になり、日本語もそのまま出せます。
- 図の種類の判定だけを行う関数。描画する前に対応しているかどうかを判定できます。

API のイメージ

package mermaid

type Options struct {
    MaxWidth    int          // px
    Scale       float64
    Face        font.Face    // nil なら内蔵の英字フォント
    Foreground  color.Color
    Background  color.Color  // nil で透過
    MaxNodes    int
}

func Detect(src string) (DiagramType, error)
func Render(ctx context.Context, src string, opt Options) (image.Image, error)
func RenderText(ctx context.Context, src string, maxCols int) ([]string, error) // 任意
const Version = "0.1.0"

var ErrUnsupported = errors.New("mermaid: unsupported diagram type")
type SyntaxError struct{ Line int; Msg string }

この形にしておけば、gvmd 側は internal/diagram/mermaid.go でこれを呼んでキャッシュし、既存の画像エンコーダに渡すだけで済みます。Mermaid の実装を待たずに、gvmd 本体の開発を先に進めることもできます。
